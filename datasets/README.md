# Datasets — Overview

This document describes each dataset in [`/datasets`](./datasets), including size, shape, and the fields most relevant to sentiment analysis and policy-sentiment prediction for Indian government policies.

| Dataset | File(s) | Size (on disk) | Shape (rows × cols) | Relevant Features | Description |
|---|---|---|---|---|---|
| **Indian Political Sentiment on Twitter** | `Indian_Political_Sentiment_on_Twitter.csv` | ~20.9 MB | 162,980 × 2 | `clean_text` (pre-cleaned tweet text), `category` (sentiment label: `-1` negative, `0` neutral, `1` positive) | The largest labeled sentiment dataset in the repo. Tweets are already lowercased/cleaned (stopwords, punctuation, mentions largely stripped). Directly usable as a **supervised training set** for a sentiment classifier — class split is roughly 72K positive, 55K neutral, 35.5K negative, so expect some class imbalance to correct for. |
| **Dataset of Indian Politics Tweets & Reactions** | `Dataset_of_Indian_Politics_Tweets_Reactions.csv` | ~12.8 MB | 50,000 × 6 | `Date`, `User`, `Tweet` (raw, unlabeled text), `Likes`, `Retweets` | Raw, **unlabeled** tweets on Indian politics (single snapshot around late March 2023) with engagement counts. Useful as unlabeled data for weak/self-supervised labeling (e.g. with a lexicon or fine-tuned model), or as an engagement-weighting signal (a tweet with high likes/retweets carries more "public voice" than one with zero). |
| **Indian Political Tweet Engagement Dataset — master_tweets.csv** | `Indian Political Tweet Engagement Dataset/master_tweets.csv` | ~22.6 MB | 85,495 × 9 | `Date`, `User`, `Tweet`, `Likes`, `Retweets`, `Target` (binary label: `0`/`1`), `Year`, `Month`, `Day` | An extended/labeled version of the tweets-and-reactions data, spanning 2022–2023, with a binary `Target` column (near-balanced: ~43K vs ~42.5K) and date parts already split out. Good for **time-based analysis** (e.g. sentiment trend before/after a policy announcement) since `Year`/`Month`/`Day` are pre-split. Note: `Target` here is binary (not the 3-class `-1/0/1` scheme used in the sentiment dataset above) — decide early whether to treat it as a true sentiment label or as something else (e.g. stance/engagement flag) since the source doesn't document it. |
| **Indian Political Tweet Engagement Dataset — network_edges.csv** | `Indian Political Tweet Engagement Dataset/network_edges.csv` | ~2.9 MB | 109,443 × 3 | `Source` (user), `Target` (mentioned/replied-to user), `Weight` (interaction count) | A **user interaction/mention network** (35,651 unique source accounts, 27,657 unique target accounts) derived from the tweet data above. Not sentiment data itself, but valuable for identifying influential accounts, echo chambers, or amplification patterns around a policy topic — could feed a network-based feature (e.g. "is this opinion from a high-centrality account") into your prediction model. |
| **Indian Gov Schemes** | `Indian_gov_schemes.csv` | ~12.9 MB | 3,400 × 11 | `scheme_name`, `details`, `benefits`, `eligibility`, `application`, `documents`, `level` (`Central`/`State`), `schemeCategory` (e.g. Social Welfare, Education, Agriculture, Business, Health), `tags` | The **policy-side corpus** — full text descriptions of ~3,400 real Indian government schemes/policies, categorized and tagged. This is what your "proposed new policy" feature extraction should be modeled on: use `schemeCategory`, `level`, and `tags` as structured policy features, and `details`/`benefits`/`eligibility` as the text to extract domain, affected groups, and economic-impact signals from. Has one unnamed/empty column (`Unnamed: 9`) that appears to carry no data. |

## Notes

- **`test`** — a placeholder file in the `datasets` folder containing only the text `"hello"`. It is not a real dataset and can be ignored or removed.
- **Row counts** were computed with `pandas.read_csv` rather than `wc -l`, since several files contain tweet text with embedded newlines inside quoted fields, which inflates a naive line count.
- **Sentiment label schemes differ** across files: `Indian_Political_Sentiment_on_Twitter.csv` uses a 3-class scheme (`-1`/`0`/`1`), while `master_tweets.csv` uses a 2-class `Target` (`0`/`1`). Standardize these into one label scheme before combining datasets for training.
- **`Dataset_of_Indian_Politics_Tweets_Reactions.csv`** and **`master_tweets.csv`** overlap substantially in their raw tweet content (same `Date`/`User`/`Tweet`/`Likes`/`Retweets` fields) — `master_tweets.csv` looks like a superset/derived version with labels and date-parts added. Worth deduplicating if using both.
